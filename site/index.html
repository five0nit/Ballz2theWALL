03 / Know the switch

More execution.
Not magic access.

Full-access settings let your agent act with fewer runtime approval stops. Use them for work and files you intend that agent to access.

O

OFF restores settings.
It is not a kill switch.

Close the agent window first. OFF restores the saved runtime configuration. It does not stop running tasks, undo completed work, or revoke OS permissions.

Understand ON / OFF ↗
Does this control my whole desktop?

No. Ballz configures supported agent runtimes; it is not a universal desktop-control layer. Your agent still needs its own tools, browser integration, and OS access. It runs with the access of the launching account—not automatic root or Administrator privileges.

What happens to my sign-in?

Your agent keeps its own OAuth or API authentication. Ballz does not copy credentials between runtime homes, create a hosted account, or log in a fresh profile for you. Select the agent profile you already use.

Is this a model-policy bypass?

No. These are native runtime execution controls, not a provider-policy bypass. Provider rules, organization policies, instruction-file guards, and tool availability still apply. OpenClaw ON changes its configured local tool allow/deny policy; OFF restores it. Changing a local setting does not change the model’s behavior or rules.

How does restoring settings work?

Ballz saves original configuration bytes and a local transaction receipt before applying settings. OFF uses the managed activation record to restore them. If files have changed since activation or receipts cannot be verified, restoration stops rather than overwriting newer edits. No task actions are undone.

What is the Mac alpha limitation?

The macOS 11+ installer uses Terminal for setup and agent launch. You must approve requested permissions yourself. The physical approval flow and Terminal attribution have not been tested on a real Mac; existing daemons or unrelated background agents do not inherit those approvals. The package is not signed or notarized.
