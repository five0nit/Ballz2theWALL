04 / Know the switch

More execution.
Not magic access.

OS permissions still apply. User access, approved Administrator access, and kernel or firmware control are different capabilities—not one blanket grant.

O

OFF revokes Ballz access.
Not completed actions.

In dev6, OFF rejects new machine calls, closes managed access and cancels session-owned direct children. It restores saved configuration—not completed work, detached descendants, unrelated agents or OS permission grants. In v0.2.0a2, OFF restores settings only.

Understand ON / OFF ↗
Does this control my whole desktop?

The dev6 source adds a local desktop/browser MCP bridge plus command and file tools. It is not unrestricted control of every OS layer: actual access depends on host permissions and driver support. Real signed-in browser use, final-candidate authenticated agent operation and physical Mac permissions remain unverified. The published v0.2.0a2 downloads only configure runtime settings.

What happens to my sign-in?

Your agent keeps its own OAuth or API authentication. Ballz does not copy credentials between runtime homes, create a hosted account, or log in a fresh profile for you. Select the agent profile you already use.

Is this a model-policy bypass?

No. These are native runtime execution controls, not a provider-policy bypass. Provider rules, organization policies, instruction-file guards, and tool availability still apply. OpenClaw ON changes its configured local tool allow/deny policy; OFF restores it. Changing a local setting does not change the model’s behavior or rules.

How does restoring settings work?

Ballz saves original configuration bytes and a local transaction receipt before applying settings. OFF uses the managed activation record to restore them. If files have changed since activation or receipts cannot be verified, restoration stops rather than overwriting newer edits. No task actions are undone.

What is still being verified?

Real Windows UAC and elevated-job cleanup, preservation of existing signed-in browser sessions, and a complete authenticated dev6 agent/tool/OFF round trip. Dependency redistribution review, final packaging and the normal downloaded-installer path also remain open. No new dev6 installer release is published.

Current verification scope ↗
Is everything local and telemetry-free?

Ballz has no hosted account service. Its machine bridge is local stdio and its Windows admin helper uses local IPC; processes start when needed. Model providers and integrations may use the network. The desktop dependency has its own telemetry behavior, so dev6 is not advertised as telemetry-free. Full dependency review is pending.

Dependency and access notes ↗
What is the Mac alpha limitation?

The macOS 11+ installer uses Terminal for setup and agent launch. You must approve requested permissions yourself. The physical approval flow and Terminal attribution have not been tested on a real Mac; existing daemons or unrelated background agents do not inherit those approvals. The package is not signed or notarized.
